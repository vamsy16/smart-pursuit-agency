# Project Management (SDLC-Style Delivery Cycle)

## Purpose
Run every client engagement like a software delivery cycle — Discover → Design → Build → Test → Deploy → Maintain — so nothing gets delivered without a QA gate, and one person can manage 3-6 concurrent retainers without dropping balls.

## When to Trigger
Continuously — this is the operating rhythm of the whole agency.

## Inputs Required
`[NUMBER_OF_ACTIVE_CLIENTS]`, `[SERVICES_PER_CLIENT]`, current tool stack

## Execution Prompt
```
Act as an agency operations consultant. I run [NUMBER_OF_ACTIVE_CLIENTS] client
retainers solo (with AI + occasional freelancers), covering [SERVICES_PER_CLIENT]
each.

1. Map our service delivery to an SDLC-style cycle for a MONTHLY retainer:
   Discover (data review) → Design (plan the month) → Build (execute) →
   Test (QA gate) → Deploy (publish/launch) → Maintain (report + optimize).
   Give me the ideal day-of-month for each phase, per client, so phases don't
   collide across multiple clients.
2. Build a weekly operating rhythm (Mon-Fri) that blocks time for: deep work
   (strategy/creative), client communication, QA review, and pipeline/sales
   activity — realistic for one operator.
3. Give me a RACI-style breakdown of what AI can own outright vs. what
   requires my direct judgment/approval at each phase.
4. Design a capacity-check formula: how do I know I'm at risk of overloading
   before accepting the next client?
```

## Deliverable Template
Monthly SDLC Cycle Calendar (per client) → Weekly Operating Rhythm table → AI-vs-Human RACI table per phase → Capacity Check Formula

## Premium & QA Notes
The "Test" phase is non-negotiable — every deliverable (report, campaign, content, ad) passes through `09-qa-testing` before reaching a client, even under time pressure. Capacity discipline is what protects quality at scale — say no to a new client rather than let quality slip on existing ₹10L/month accounts.
